# 情侣全球旅行点亮地图 · 设计规格

日期：2026-08-09  
形态：可安装 PWA（手机主屏）  
状态：已确认产品决策，待实现计划

---

## 1. 目标

做一本「两人共用的旅行账」：世界地图上，去过的国家淡色点亮、去过的城市用可爱标记亮起；没去过的保持暗。支持持续添加新地点，并通过邀请码在两台手机间同步。

成功标准（第一期）：

- 两人能加入同一情侣本，各自绑定兔子 / 线条小狗
- 能搜索或长按地图添加国家/城市，并标记「我 / 对方 / 一起」
- 地图即时反映点亮状态；一起去过有统一金色特别标记
- 可换标记套装；默认星星
- 离线可看本地数据，联网后同步

---

## 2. 用户与角色

| 角色形象 | 颜色 | 说明 |
| --- | --- | --- |
| 兔子 | 粉玫瑰光 `#F5A0BF` | 首次加入时自选身份，之后固定 |
| 线条小狗 | 天空蓝光 `#8CC8FF` | 同上 |
| 一起去过 | 金色特别标 `#FFD278` | 不可改色，保证「共同」一眼可辨 |

同一情侣本仅两名成员。创建者生成邀请码；加入者输入码或打开分享链接后选择身份。

---

## 3. 范围

### 3.1 第一期做

- PWA：全屏暗夜纪念册地图 + 底部信息卡
- 国家淡色填充 + 城市标记（默认星星套装）
- 标记套装：星星（默认）、票根邮戳、角色本体（设置可切换）
- 地点字段：国家/城市、坐标、访客类型（兔子 / 小狗 / 一起）、可选日期备注
- 添加：搜索为主；长按地图为辅
- 筛选：只看兔子 / 只看小狗 / 一起 / 全部
- 同步：6 位邀请码 + 分享链接；本地缓存 + 轻量云
- 底部卡展示：已点亮国家数、城市数、一起去过数量

### 3.2 第一期不做

- 正式账号（邮箱/手机登录）
- 逐日行程、交通、住宿
- 照片相册
- 原生 iOS/Android 商店包
- 二维码加入（可二期叠加）

---

## 4. 信息架构与关键界面

### 4.1 首页（地图）

- 布局：全屏地图 + 底部信息卡（风格：暗夜纪念册）
- 顶栏：双人形象「我们的地图」；右上角「+」
- 底部卡：统计 + 筛选 chips
- 未去过：暗底不亮；已去国家：淡色块；已去城市：套装标记（带角色色光）

### 4.2 添加地点

1. 点「+」打开搜索面板，或长按地图打开确认面板
2. 确认国家/城市
3. 选择访客：兔子 / 小狗 / 一起
4. 可选填写日期备注
5. 点「点亮」写入本地并排队同步；地图动画点亮

### 4.3 设置 / 情侣本

- 查看/复制邀请码、分享链接
- 切换标记套装
- 查看本机角色（第一期不做改绑，仅首次选择）

### 4.4 加入流程

- 打开分享链接或输入 6 位邀请码
- 选择「我是兔子」或「我是小狗」（若该角色已被占用则提示选另一个）
- 进入同一本地图

## 5. 架构

```
PWA (Vite + React)
  - MapLibre + GeoJSON countries
  - Local store (IndexedDB / localStorage)
        |
        | sync when online
        v
Lightweight backend (Supabase preferred)
  - couple_books / members / places
  - invite_code uniqueness
```

选型理由：前端可快速做出暗夜地图与 PWA；Supabase 提供表存储与简易实时/轮询同步，无需自建账号体系，契合「邀请码共享」方案。

备选：Firebase（Firestore + Auth 匿名）。实现计划阶段锁定一家，避免双轨。

---

## 6. 数据模型

### CoupleBook

- `id`
- `invite_code`（6 位，大写字母数字）
- `marker_pack`：`stars` | `stamps` | `animals`
- `created_at`

### Member

- `id`
- `book_id`
- `role`：`rabbit` | `dog`（唯一约束：每本每角色一人）
- `device_token` 或匿名 client id（用于本机识别，非正式登录）
- `joined_at`

### Place

- `id`
- `book_id`
- `place_type`：`country` | `city`
- `name`
- `country_code`（ISO）
- `lat` / `lng`（城市必填；国家可用代表点）
- `visitor`：`rabbit` | `dog` | `together`
- `visited_on`（可选，日期备注）
- `updated_at`（冲突时以后写入为准）

规则：

- 若先有「仅兔子」再标记小狗也去过，升级为 `together`（第一期采用单条升级，简化）
- 国家点亮：该国存在任意 Place（国家记录或下属城市）即淡色填充
- 城市标记：每个城市一条 Place

---

## 7. 同步与冲突

- 写路径：先写本地，标记 dirty，在线时 upsert 云端
- 读路径：启动与前台恢复时 pull；可选短轮询或 Realtime
- 冲突：同一 `place.id` 以 `updated_at` 较新者覆盖，并提示「已同步最新」
- 离线：允许添加/筛选/查看；分享与加入需在线
- 邀请码无效或本已满员：明确错误文案

---

## 8. 视觉与动效

- 整体：暗夜底 `#121826`，卡片半透明毛玻璃
- 点亮瞬间：短星光/放大淡入（克制，2–3 处有意动效）
- 标记套装：SVG/emoji 映射表；后期可换定制插画而不改数据模型
- 线条小狗与兔子：第一期可用高质量 emoji/简笔 SVG；二期可换定制插画

---

## 9. 非功能

- 移动端优先；桌面可浏览
- PWA：manifest + service worker（静态资源缓存；地图瓦片按需）
- 性能：国家 GeoJSON 需简化或按需加载；城市点过密时做聚合
- 隐私：不收集正式个人信息；链接持有者可加入（第一期接受；二期可加过期码）

---

## 10. 测试要点

- 双设备：创建、邀请、双方加点后地图一致
- 访客升级：兔子地点再标一起后出现金色特别标
- 离线加点，恢复网络后同步
- 套装切换后样式变化、数据不丢
- 长按与搜索两条添加路径结果一致
- 邀请码占用角色、满员、错误码
